# Talent Forge

Конструктор вымышленных классов в стиле World of Warcraft: Wrath of the Lich King. Редактор работает в браузере; аккаунты и проекты сохраняются сервером в SQLite.

## Запуск

Нужен **Python 3.12 или новее**. Для обработки загружаемых администратором изображений нужен Pillow из `requirements.txt`. Отдельный сервер базы не требуется.

```sh
git clone https://github.com/sergeraylenyaru/talenttree_creator.git
cd talenttree_creator
python3 -m pip install -r requirements.txt
python3 server.py
```

Открыть **http://localhost:8000**. На Windows можно использовать `py server.py`.

SQLite автоматически создаётся в `data/talents.sqlite3`. Для резервной копии остановить сервер и скопировать этот файл. База, аккаунты и локальные файлы не входят в Git.

## Возможности

- Новый класс: две ветки, пять рядов, четыре ячейки в ряду.
- До четырёх веток; добавление и удаление рядов. Технический предел — 1000 рядов на ветку.
- Названия класса и веток, лимит очков и стоимость открытия рядов.
- Таланты: иконка, название, 1–100 рангов, отдельное описание каждого ранга, зависимость от другого таланта той же ветки. Поддерживаются зависимости в одном ряду, циклы запрещены.
- Калькулятор: левая кнопка добавляет очко, правая или Shift + клик снимает. Проверяются требования рядов, полный ранг предшественника, лимит очков и зависимые таланты.
- Список способностей: название, описание, иконка, ресурс, время применения, перезарядка, дальность, связь с талантом.
- Общий каталог из более 1600 иконок с поиском, ввод имени любой WoW-иконки, загрузка своих изображений отключена. Это каталог талантов всех поставляемых версий, не полный архив клиента.
- Импорт 28 наборов классов из 3.3.5a, TBC 2.4.3 и Forever: 1876 талантов, описания рангов, позиции и зависимости. Английские исходные названия и описания; загружается редактируемая копия. Базовые способности не входят в набор.
- Регистрация по логину и паролю, вход, выход, список своих классов, копирование и удаление. Сохраняются дерево, способности и текущее распределение очков.
- Черновик в localStorage, импорт/экспорт JSON. Черновик привязан к браузеру, не к учётной записи.
- Публичная ссылка на снимок класса без распределённых очков. Открывается без аккаунта; последующие правки оригинала не меняют снимок. Создание ссылки явно подтверждается в интерфейсе.

## Проверки

Python проверяет HTTP API, регистрацию, вход, хранение паролей, изоляцию проектов, выход, общий доступ и валидацию исходных данных:

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
```

Для проверки калькулятора и всех стандартных деревьев нужен Node.js 22+:

```sh
node --test tests/*.test.js
```

## Настройка и размещение

Переменные окружения: `PORT` (8000), `HOST` (127.0.0.1), `TALENT_DB` (путь к SQLite), `COOKIE_SECURE=1` (Secure-cookie для HTTPS). Их нужно устанавливать средствами системы/хостинга; `.env` автоматически не читается.

Это первая локальная версия. Сервер стандартной библиотеки Python предназначен для разработки. Для публичной эксплуатации нужны поддерживаемый сервер приложения или перенос API на подходящий фреймворк, HTTPS, постоянный диск для SQLite и резервные копии. GitHub Pages не запускает Python и не обеспечивает аккаунты/сохранение. Не размещайте файл базы в статической папке `static/`.

Ограничение первой версии: у класса хранится одно текущее распределение очков; отдельные варианты можно сохранить копиями класса, экспортировать или передать ссылками-снимками. Способности имеют одно описание и набор характеристик; отдельные ранги способностей и русский перевод стандартных талантов пока не реализованы. Боевые эффекты не исполняются и не симулируются.

## Обновление редактора

Ряды добавляются одновременно во все ветки. Новая ветка получает общее число рядов. Стрелки зависимостей идут по свободным ячейкам под прямыми углами; занять ячейку стрелки нельзя до снятия зависимости. Существующие деревья сохраняют свои таланты.

«Ресурсы и персонаж»: здоровье, раса, пол и список ресурсов. Для каждого — название, максимум, начальное количество, цвет, полоска или символы (круг/ромб/треугольник). Панель видна справа в калькуляторе, на узком экране ниже деревьев. 3D-модель и импорт экипировки пока не подключены; ссылка на персонажа сохраняется как внешняя ссылка.

В калькуляторе пустые ячейки скрыты, подсказки талантов и способностей появляются мгновенно. Характеристики способностей подписаны.

## Перетаскивание, избранное и новые наборы

- В редакторе перетащите талант на пустую ячейку или другой талант. Во втором случае они поменяются местами. Идентификаторы и описания сохраняются. Перемещение, нарушающее зависимости или занимающее путь стрелки, отклоняется с объяснением.
- Откройте талант или способность и нажмите «В избранное». Заполненный элемент сохраняется в текущем классе и независимой копией в аккаунте. В меню «Избранное» выберите «Добавить»: способность добавляется в список, талант размещается нажатием на пустую ячейку. В окне нового таланта также есть «Взять из избранного». Старые зависимости не переносятся.
- У новых способностей стоимость, время применения, восстановление и дальность — неотрицательные числа. Ресурс выбирается рядом со стоимостью: здоровье, мана, энергия, ярость или пользовательский ресурс класса. Название и описание остаются текстовыми. При редактировании старых записей числовая часть прежних текстовых полей предлагается для сохранения в новом формате.
- В стандартных классах доступны 3.3.5a (10 классов), TBC 2.4.3 (9 классов), Forever (9 классов, снимок 1.60.1.69876). Ограничения и источники указаны в SOURCES.md. Весь каталог содержит 1876 талантов.
- Иконки из всех этих деревьев доступны в одном окне выбора, даже до импорта класса; поиск по английским названиям талантов и русским названиям классов. Базовые русские поисковые слова сохранены.
- При пяти деревьях панель здоровья занимает отдельную колонку; деревья прокручиваются внутри своего контейнера.

Таблица избранного создаётся автоматически при запуске сервера. Существующая SQLite-база и сохранённые классы не удаляются.

## Выбор классов, гостевой режим и история

В окне стандартных деревьев сверху переключатели Forever / TBC / WotLK, ниже карточки классов с иконками. Гости могут открывать стандартные деревья и публичные ссылки и распределять очки. Создание, редактирование, импорт, экспорт, избранное и сохранение требуют входа.

Новый пустой класс имеет 41 очко для пяти рядов, каждый дополнительный ряд добавляет пять. В «Ресурсы и персонаж» можно изменить лимит, увидеть рекомендуемое значение и включить автоматический расчёт. Ручная правка отключает автоматический расчёт; готовые стандартные классы сохраняют исходные лимиты 51/61/71.

Отмена и повтор: кнопки в панели, Ctrl+Z и Ctrl+Y (или Ctrl+Shift+Z вне текстовых полей). Хранятся последние 100 действий в памяти текущей страницы. Перезагрузка/закрытие страницы очищает историю; сохранения аккаунта остаются. Отмена не удаляет уже сохранённые проекты, избранное или серверные счётчики — она меняет текущий документ.

Для ресурсов доступны круг, треугольник, ромб, кристалл, самоцвет, сфера, пламя и звезда с выбором цвета. Загрузка пользовательских иконок отключена в интерфейсе и API. Встроенные картинки Forever остаются доступными. Подпись об источнике 3.3.5a убрана из подвала; сведения об источниках сохранены в SOURCES.md.

У публичной копии показываются «Распределяли очки» и «Сохранили себе». Первый счётчик считает браузеры с постоянной HttpOnly-cookie, впервые добавившие очко; это приближение к числу людей, а не подтверждение личности. Очистка cookie или другой браузер даёт отдельного посетителя. Второй считает уникальные аккаунты, сохранившие копию. Счётчики начинают собираться после обновления и видны при открытии ссылки. Новые таблицы SQLite создаются автоматически, старые документы не удаляются.

Автоматический перевод в этом обновлении не реализован. Предложенная схема: оригинальный текст отдельно от английского перевода, серверный перевод через API провайдера по явному запросу/публикации, кеш по версии исходного текста, сохранение чисел и шаблонных переменных, ручная корректировка и переключатель «Оригинал / English». API-ключ хранится на сервере.

## Четыре ветки в строку

Максимум для создания, импорта и сохранения — четыре ветки. На экранах от 1280 пикселей все четыре помещаются в одну строку рядом с отдельной колонкой показателей; размеры ячеек и отступы адаптируются к ширине. На узких экранах показатели расположены под деревьями, а на телефоне деревья прокручиваются внутри своего контейнера.

Старые сохранения и черновики с пятью ветками остаются в базе и открываются без удаления данных. Перед новым сохранением интерфейс просит удалить лишнюю ветку. Стандартные классы с тремя ветками работают без изменений.

## Одно описание для всех рангов

Новый талант открывается в режиме «Один текст, разные числа». Напишите, например, «Увеличивает урон на 2%», выделите 2 и нажмите «Сделать число изменяемым». Поля «Начало 2, шаг 2» сразу задают 2, 4, 6 и т.д. Результат виден по кликам на иконку справа. Поддерживаются несколько меняющихся чисел, отрицательные значения и дроби с точкой или запятой. Предпросмотр показывает выбранный ранг, таблица больше не используется.

Старые таланты открываются с отдельными описаниями. При переключении на общий текст редактор автоматически распознаёт отличающиеся числа, если формулировки одинаковые. Если меняются слова, он сначала просит подтверждение перед использованием текста первого ранга. Можно вернуться к отдельным текстам. Исходный талант меняется только после сохранения.

В JSON сохраняются и общий текст с числами (`rankTemplate`), и готовые описания всех рангов (`descriptions`). Сервер проверяет их соответствие. Это работает с аккаунтом, избранным, ссылками и экспортом.

При одной, двух или трёх ветках их ширина остаётся такой же, как при четырёх: ветки прижаты влево, оставшиеся места справа пустые. На телефоне сохраняется фиксированная ширина 190 пикселей и прокрутка только существующих веток.

## Живой предпросмотр и способности в талантах

Таблица значений рангов удалена из редактора. Справа от общего описания — иконка таланта и текущая подсказка: клик добавляет ранг, правый клик или Shift+клик снимает, «Сбросить» возвращает ноль. Поля «Начало» и «Шаг» сразу пересчитывают ранги и предпросмотр. При появлении обычного числа в тексте кнопка «Сделать число изменяемым» подсвечивается; без выделения выбирается число рядом с курсором или последнее число в описании. Числа внутри уже созданных подстановок не учитываются. Старые вручную заданные нелинейные значения сохраняются, пока автор не изменит правило. Для произвольных текстов остаётся режим отдельных описаний.

В редакторе способность из списка можно перетащить на ячейку дерева. Занятое место заменяется только после подтверждения. Либо откройте ячейку и нажмите «Добавить способность»: откроются иконки созданных способностей, а кнопка «Добавить способность» в этом окне позволяет создать новую. При возврате черновик таланта сохраняется. При выборе копируются название, иконка и описание, создаётся талант с одним рангом, а способность связывается с его изучением. Повторное размещение использует ту же способность; новая запись в списке не создаётся.

## Способность — единый источник данных

Размещение способности в дереве хранит ссылку `grantedAbilityId` на запись из списка способностей. В окне размещения можно настроить только зависимость или убрать это размещение. Название, иконка, описание, стоимость и другие характеристики редактируются только в самой способности и сразу обновляют все её размещения. Поля отображения в JSON остаются совместимым кешем, который клиент и сервер пересчитывают из способности. Повторное добавление не создаёт дублей. Способность становится доступна после изучения любого из её размещений.

Полностью одинаковые старые записи, обе используемые размещениями, объединяются при загрузке класса: ссылки переназначаются, позиции и зависимости остаются. Различающиеся записи не объединяются. Удаление способности с подтверждением удаляет её размещения и очищает зависимые стрелки; удаление одной ячейки не удаляет саму способность. При перетаскивании используется отдельная иконка 48×48 без описания и прочих полей карточки.

## Маршруты стрелок и состояния рамок

Все стрелки ветки планируются совместно. Они не проходят через таланты, не пересекаются в пустых ячейках и не используют общий отрезок. Несколько стрелок могут выходить из одной иконки разными сторонами. Для маршрутов проверяются несколько детерминированных порядков прокладки; если совместный свободный маршрут не найден, зависимость недоступна для выбора и отклоняется при сохранении на сервере. Во всех 28 стандартных наборах маршруты проверены без пересечений.

Старые документы с невозможными маршрутами открываются с предупреждением: конфликтующая стрелка не рисуется, а для нового сохранения нужно изменить зависимости. Существующая проблемная зависимость не снимается автоматически.

В калькуляторе доступный талант имеет зелёную рамку и зелёный счётчик. Частично изученный остаётся зелёным; максимум — золотая рамка и жёлтый счётчик; недоступный — серая рамка, серый счётчик и обесцвеченная затемнённая иконка. Способности отличаются рамкой 4 px вместо обычных 2 px во всех состояниях. Активные связи — золотые объёмные стрелки с тёмной окантовкой, неактивные — серые. Состояния сразу меняются при распределении и снятии очков.

## Публикации, рейтинг и оценки

«Зафиксировать и опубликовать» сохраняет рабочий класс и создаёт неизменяемую версию без распределённых очков. По умолчанию выбирается «Только по ссылке». «Общедоступное» включает публикацию в рейтинг. Последующие правки рабочего проекта не меняют старые версии; повторная публикация того же проекта получает следующий номер и отдельную статистику. Обычное сохранение в аккаунте не публикует класс.

В «Рейтинг деревьев» четыре сортировки за всё время: лайки, уникальные просмотры, уникальные пользователи калькулятора, последние публикации. Четыре равные вкладки занимают всю ширину списка. Показываются только общедоступные версии, по 20 строк на страницу. Каждая публикация занимает две строки: название класса и иконки веток сверху; показатели слева и автор с круглым аватаром справа снизу. Просмотр карточки не засчитывает открытие дерева; открытие калькулятора засчитывает один просмотр для браузера. Счётчики просмотров и использования привязаны к постоянной cookie посетителя, сохранения — к аккаунту. Это приближение к людям: другой браузер или очистка cookie считаются другим посетителем.

В «Мои публикации» видны ссылки, статистика, лайки и дизлайки; можно менять видимость и переходить к исходному рабочему классу для следующей версии. Переключение на «Только по ссылке» исключает версию из всех рейтингов, сохраняя ссылку, голоса, показатели и исходную дату. Возвращение в общедоступный режим не поднимает дату в «Последних опубликованных».

Для лайка/дизлайка нужен вход. Один аккаунт имеет один голос; повторное нажатие снимает голос, противоположная кнопка заменяет оценку. Автор не оценивает свою публикацию. Лайки видны всем. Число дизлайков сервер возвращает только автору в его запросах; остальные видят только собственный выбор. Дизлайки не участвуют в трёх сортировках и не раскрываются через общий итоговый балл.

SQLite обновляется при запуске без удаления сохранений. Старые ссылки остаются «Только по ссылке». У ссылок старой версии приложения автор не был записан, поэтому им не назначается владелец задним числом: они продолжают открываться, но не появляются в личном списке публикаций. Автор может открыть свой рабочий класс и явно выпустить новую управляемую публикацию. Ни один старый класс не становится общедоступным автоматически.

## Иконки веток и компактные способности

В редакторе нажмите на иконку слева от названия ветки, выберите изображение из каталога и сохраните. Иконка хранится отдельно в `branch.icon`, используется в заголовке дерева, блоке способностей и карточке опубликованной версии. Старые деревья без отдельной иконки используют первый талант или знак вопроса. Изменение рабочего класса не меняет иконки уже опубликованных снимков.

Рейтинг дополнен вкладкой «По рейтингу» — число лайков по убыванию. Учитываются только положительные оценки общедоступных версий; дизлайки по-прежнему видны только автору. Шапка сайта закреплена при прокрутке.

У способности появились «Тип» (активная/пассивная) и «Ветка». Можно выбрать конкретную ветку, «Общая — без ветки» или «По размещению в дереве». Автоматическая принадлежность учитывает все размещения одной способности, не создавая новых записей. Если размещений нет, способность остаётся в общих. Старые способности по умолчанию активные и используют автоматическую принадлежность. При удалении ветки явно привязанные к ней способности переходят в общие; избранное не переносит идентификатор ветки другого класса.

В калькуляторе список способностей по умолчанию состоит из иконок с мгновенными подсказками. Сверху есть переключатель «Иконки / Подробно». В редакторе остаются подробные карточки. Способности разложены по горизонтальным полосам в цветах веток, с крупной иконкой слева и разделителем; внутри каждой полосы сначала активные, затем пассивные. Полос столько, сколько веток класса; при необходимости добавляется отдельная полоса общих способностей. Учитывается доступность способности по вложенным очкам.

### Аватар профиля

Нажми на круг рядом с ником в шапке: откроется тот же конструктор, что у эмблемы класса. Доступны до двух иконок из общего каталога, независимая прозрачность, перемещение, поворот и размер 75–150%. Итог обрезается по кругу. Собственная загрузка изображений отключена. Аватар хранится в профиле и обновляется во всех публикациях автора. При запуске существующие аккаунты автоматически получают стандартный аватар; пароли и сохранения сохраняются.

### Оформление и переходы

Интерфейс использует тёмные панели с золотыми акцентами, локальную SVG-иллюстрацию золотой сферы и шкалу распределения очков. Раздел сохранений называется «Мои деревья». Открытие дерева или его копии из этого раздела возвращает редактор, в том числе поверх рейтинга; открытие публикации нажатием на название или свободную область строки включает калькулятор. При переходе к рабочему дереву ссылка опубликованной версии убирается из адреса.

Отдельная браузерная проверка этих переходов: `python3 tests/browser_navigation.py` (необязательные инструменты разработчика: Playwright и Chromium; путь к браузеру задаёт `CHROMIUM_PATH`). Проверка использует временную базу.

### «Только мне», подсказки и эмблема класса

При фиксации версии и в «Моих публикациях» доступны три режима: «Общедоступное», «Только по ссылке» и «Только мне». Личную версию открывает только автор после входа; ссылки, взаимодействия, голоса и счётчик сохранений проверяют доступ на сервере. Личная версия не появляется в рейтинге. Переключение режима сохраняет статистику и номер версии. Ранее скачанные файлы и независимые копии других пользователей сменой видимости не удаляются.

В редакторе наведение на талант показывает описание первого ранга и требования; в калькуляторе — изученный ранг и следующий. Эмблема выбирается нажатием на золотой кружок слева от названия класса. Доступны один или два наложенных слоя, непрозрачность каждого 0–100% и живой предпросмотр. Настройки сохраняются в документе, JSON и зафиксированной версии. У старых деревьев без своей эмблемы используется иконка первой ветки. Самостоятельная загрузка изображений по-прежнему отключена.

Общий каталог дополнен 194 иконками оружия и щитов (173 новых для общего выбора с учётом стартовых иконок). Во всех окнах выбора есть фильтр «Оружие и щиты», в том числе для талантов, способностей, веток, аватаров и слоёв эмблемы.

Дополнительная браузерная проверка: `python3 tests/browser_emblem.py` (Playwright и Chromium, временная база).

### Положение слоёв, архив и чужое избранное

В редакторе эмблемы каждый слой можно перетаскивать мышью/пальцем, двигать ползунками X/Y, масштабировать от 75% до 150% и вращать на −180…180° вокруг центра круга. Для клавиатуры доступны стрелки в предпросмотре и Shift для более крупного шага. Сплошная заливка и фоновое свечение удалены. Старые поля `background` и `glow` принимаются для совместимости, но не отображаются. Слой выбирается нажатием на одну из двух миниатюр с золотым выделением; рядом с предпросмотром расположены вертикальные ползунки непрозрачности, размера, поворота и сдвига X/Y. Карандаш на миниатюре меняет изображение. Все параметры сохраняются в JSON; прежние двухслойные эмблемы поддерживаются.

В дереве верхний блок показывает название класса, иконки веток и правила очков; справа находится эмблема. Приветственный текст остаётся в разделах со списками. Создание дерева и загрузка стандартного класса доступны из меню «Дерево» в панели редактора.

В «Моих публикациях» есть вкладки «Публикации» и «Архив». Архив скрывает снимок из рейтинга и закрывает ссылку для других пользователей, сохраняя прежнюю видимость и статистику. Восстановление возвращает те же ссылку, версию и видимость. Без восстановления через 30 × 24 часа снимок и его статистика удаляются, рабочее дерево и чужие независимые копии остаются. Повторная отправка уже архивного снимка не продлевает срок. Штатный сервер проверяет истечение срока раз в минуту, а также при запуске и запросах API. Нумерация новых версий не сбрасывается после удаления старых снимков.

Из чужого доступного дерева можно сохранять элементы в своё избранное: в калькуляторе открыть талант через Alt + клик; у способности открыть окно просмотра и нажать кнопку сохранения. Если выбран талант, открывающий способность, сохраняется исходная способность. Вход или регистрация продолжают выбранное действие. Очки и дерево автора не меняются; копируются все ранги обычного таланта без исходных зависимостей.

Дополнительная сквозная проверка: `python3 tests/browser_archive_transform.py` (Playwright, Chromium и временная SQLite-база).

Карточки рейтинга показывают крупную круглую эмблему с названием класса под ней, ветки в верхней строке и показатели в нижней. Справа находятся отметка лидера и автор с аватаром. Длинные названия сокращаются, на узких экранах сохраняется компактная компоновка. Надписи «ДЕРЕВО ТАЛАНТОВ» и «АРСЕНАЛ КЛАССА» из редактора удалены.

### Калькулятор сохраняется в браузере

У нового посетителя опубликованное дерево открывается с нулём распределённых очков. Личный билд автоматически сохраняется в `localStorage` отдельно для каждой ссылки и рабочего дерева: он восстанавливается при повторном открытии в том же браузере, сброс и отмена тоже сохраняются. В другом браузере или после удаления данных сайта калькулятор начинается с нуля. Некорректный билд после изменения правил дерева сбрасывается.

Сохранение в аккаунте, публикация и экспорт JSON содержат структуру класса с пустым `build`. Старые ссылки также игнорируют распределение автора; повторная публикация не нужна. На сервер отправляется только факт использования калькулятора для существующего счётчика, без выбранных рангов. Проверка независимости посетителей: `python3 tests/browser_build.py` (временная база, Playwright и Chromium).

### Цвета веток и возврат к редактору

В верхнем блоке разделов рядом с «Создать» находится единая кнопка «Вернуться к редактору». Она открывает текущее дерево, сохраняя черновик и режим работы; прежние кнопки возврата внутри списков удалены.

В шапке каждой ветки редактора кнопка ◐ открывает оттенок фона: произвольный цвет, восемь готовых вариантов, предпросмотр и возврат к стандартному оформлению. Тот же оттенок применяется к полосе способностей этой ветки. Цвет сохраняется в аккаунте, JSON и публикации; в калькуляторе менять его нельзя. Старые деревья без `branches[].color` сохраняют прежнюю палитру. Цвет проверяется на клиенте и сервере (`#RRGGBB`).

Проверка конструктора аватара, цветов и навигации: `python3 tests/browser_customization.py`. Удаление чёрного фона игровых изображений пока не реализовано: обсуждаются смешивание «Осветление», пороговая прозрачность и отдельный каталог PNG.

### Компактный калькулятор и настройки профиля

В калькуляторе скрыты «Дерево», история, публикация, импорт/экспорт, сохранение и настройки ресурсов. В редакторе они остаются доступны. Переключатели «Все ветки» и масштаба удалены; ветки по-прежнему автоматически размещаются по ширине экрана. Заголовок секции деревьев и инструкция распределения в калькуляторе убраны. В верхнем блоке название класса переносится по необходимости, а в карточке рейтинга получает две строки; поле редактирования многострочное. «Иконки / Подробно» находятся на строке «Способности», подзаголовок удалён.

Звезда рядом с «Калькулятором» доступна только после входа и сразу сохраняет всё дерево в избранное с уведомлением. Повторный клик не создаёт дубликат. В разделе «Избранное» есть фильтр «Деревья» и действие открытия калькулятора. Для опубликованного дерева открывается исходная ссылка с проверкой доступа; для неопубликованного сохраняется независимая копия структуры. Распределённые очки в избранное не попадают и хранятся только в браузере. Избранные деревья не предлагаются как таланты в окне размещения. Отдельные таланты по-прежнему можно копировать через Alt + клик и окно просмотра.

Меню аккаунта → «Настройки профиля» содержит переключатель «3D-просмотр». По умолчанию он выключен у новых и существующих аккаунтов, у гостей блок скрыт. Настройка хранится в аккаунте. Пока это показ/скрытие блока персонажа; движок 3D-моделей ещё не подключён, что указано в настройке.

Регрессия: `python3 tests/browser_calculator_layout.py` — скрытые панели и восстановление редактора, звезда и избранное, настройка профиля, две строки названия и адаптивность 320–1440 px.

### Сведения о публикации и оценки в шапке

Автор, версия, видимость, просмотры и счётчики использования/сохранений расположены под единственным названием класса в шапке. Кнопки лайка и дизлайка находятся под круглой эмблемой класса. Все видят число лайков; число дизлайков выводится рядом с кнопкой только владельцу. Пояснение «Видно только создателю дерева» находится в подсказке при наведении владельца, постоянной подписи нет. Сервер по-прежнему не выдаёт число дизлайков другим пользователям. При выходе владельца старые кнопки скрываются до обновления данных посетителя.

В панели здоровья повторные эмблема и название класса удалены. У полос способностей видимое название ветки удалено, оставлены доступное название для экранного диктора и подсказка при наведении на иконку. Иконка ветки 144 px, иконки способностей 48 px в обоих режимах. Между ними вертикальная линия на широком экране и горизонтальная на мобильном.

Проверка: `python3 tests/browser_publication_header.py` — голосование, автор/посетитель/выход, скрытое число дизлайков, расположение данных, соотношение иконок 3:1 и отсутствие горизонтального переполнения при 320–1440 px.

### Плотная шапка без пустой строки

Короткое название класса в шапке занимает одну строку без резерва под вторую; длинное переносится по ширине. Под ним автор, версия и статистика собраны в одну компактную строку на широком экране и переносятся на узком. Видимая подпись «Название класса» отсутствует, поле сохраняет доступное имя через aria-label. Кнопки «Редактор / Калькулятор / ★» вынесены над карточкой деревьев на прозрачный фон; при переходе в списки этот блок скрывается. Сохранение и остальные действия редактора остаются внутри его панели.

### English / Русский

Интерфейс по умолчанию английский, в том числе у существующих аккаунтов после миграции. Меню аккаунта → Profile settings / Настройки профиля → Interface language / Язык интерфейса → English или Русский → Save / Сохранить. Выбор хранится в аккаунте и применяется после входа; браузер также помнит последний выбранный язык. У нового гостя — English. Переводы интерфейса встроены в `static/translations.js`, внешний переводчик и ключи API не нужны. ### Окно несохранённого черновика

При открытии другого дерева, публикации, импорте или создании нового вместо подтверждения браузера появляется окно с названием несохранённого дерева и тремя действиями: сохранить перед переходом, перейти без сохранения, вернуться к редактору. Сохранение ожидает успешного ответа сервера; при ошибке окно остаётся открытым с сообщением и повторной попыткой. Если нужен вход, его можно выполнить перед сохранением. Escape возвращает к редактору. Признак несохранённых правок переживает перезагрузку в этом браузере. Обычное распределение очков калькулятора не считается изменением структуры и не вызывает такое окно. Подтверждения удаления отдельных элементов пока остаются стандартными.

### Конструктор персонажа

«Resources & character / Ресурсы и персонаж» — компактное окно: слева интерактивное здоровье и ресурсы, справа свойства выбранного элемента. Нажатие на полоску или фигуры выбирает ресурс; «+» добавляет новый. Настраиваются тип, название, максимум, начальное значение, единицы (`%`, `ед.`, `шт.`), полоска/фигуры, форма и цвет. Предпросмотр обновляется сразу. Ресурсы показываются по три на страницу, поэтому их количество не растягивает окно.

На вкладке Character / Персонаж находятся раса, пол, ссылка и бюджет талантов с автоматическим расчётом по рядам. Equipment / Экипировка задаёт **разрешённые типы**, а не предметы: ткань, кожа, кольчуга, латы, щиты; одноручные и двуручные мечи/топоры/дробящие, кинжалы, посохи, древковое, кистевое, луки, арбалеты, ружья, жезлы, метательное и предметы в левую руку. Можно отметить несколько типов. У доспехов и оружия есть «+ Custom option / Свой вариант»: название и иконка из общего каталога, включение/выключение и редактирование. Личные изображения загружать нельзя.

Новые данные: `character.armorTypes`, `weaponTypes`, `customArmorTypes`, `customWeaponTypes`; у ресурса `unit: points|percent|count`. Собственный тип имеет `id`, `name`, `icon`, `enabled`. Параметры сохраняются в аккаунте, JSON и публикациях, проверяются клиентом и сервером. Старые деревья без этих полей поддерживаются. При выборе стоимости способности также доступны единицы `points|percent|count` через `resourceUnit`.

Проверки: `python3 tests/browser_international_builder.py` — языки, сохранение предпочтения, неизменность авторских текстов, три действия черновика и ошибка сохранения, конструктор на 1440×1000, 1024×768, 768×600, 390×844 и 320×700 без прокрутки окна. Вкладки и страницы экипировки/ресурсов переключают содержимое вместо длинного списка.

### Уточнения конструктора экипировки и ресурсов

У стандартных типов экипировки появились соответствующие WoW-иконки; новые имена иконок доспехов, метательного и левой руки добавлены в общий каталог. У собственного типа есть отдельная кнопка «Save and return / Сохранить и вернуться»: проверяет название и возвращает к списку, не закрывая конструктор. Общая кнопка Save по-прежнему применяет все настройки персонажа.

Количество типов на странице теперь зависит от доступного места: все стандартные виды оружия показываются сразу на широком экране, страницы появляются только при необходимости и пересчитываются при изменении окна. Выбор не сбрасывается. Новые ресурсы, включая начальную ману, и новая стоимость способности используют `%` по умолчанию; прежние явно выбранные единицы не меняются.

Для фигур допускается максимум 20. При переключении полоски в фигуры максимум и начальное значение уменьшаются до 20, поле ограничивается этим числом; клиент и сервер проверяют предел. В старых сохранённых деревьях количество фигур выше 20 безопасно ограничивается при открытии, без переписывания исходной публикации. Полоски сохраняют прежний числовой предел.

Проверки: `python3 tests/browser_equipment_refinement.py` — стандартные иконки, отсутствие лишних страниц, адаптация при изменении размеров, сохранение собственного варианта и возврат, `%` по умолчанию и предел фигур.

## Администратор и регистрация по почте

Регистрация теперь требует почту, публичный ник и пароль (8–128 символов); форма повторяет пароль и позволяет его показать. Почта не отображается в рейтингах. Вход принимает почту или прежний логин: существующие аккаунты и хеши паролей сохранены. В профиле видны почта и статус подтверждения; адрес можно добавить/сменить с текущим паролем. Смена адреса завершает прежние сессии и снимает подтверждение.

### Первый администратор

На том же сервере, с тем же `TALENT_DB`, остановить прежний процесс, обновить код и установить зависимости. На Ubuntu рекомендуется отдельное виртуальное окружение:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --create-admin
.venv/bin/python server.py
```

В Windows без виртуального окружения: `python -m pip install -r requirements.txt`, затем `python server.py --create-admin`. Команда интерактивно запрашивает почту, новый публичный ник и пароль дважды; пароль при вводе скрыт. Готового общего пароля или публичной регистрации администратора нет. Команда создаёт отдельный новый аккаунт, ник и адрес должны быть свободны. Она работает до настройки SMTP.

После запуска открыть **`/admin`** и войти администратором. Это отдельная двухчасовая сессия, независимая от обычного сайта. У администратора в основном меню также появляется ссылка Administration / Администрирование. Новых администраторов можно назначать из списка пользователей.

### Управление

В Users: поиск по нику/почте, страницы по 20 пользователей, блокировка/разблокировка, завершение сессий, изменение ника и почты, назначение/снятие роли администратора, удаление пользователя. Нельзя заблокировать, удалить или понизить собственный аккаунт либо отключить последнего активного администратора. Блокировка и чувствительные изменения отзывают сессии. Удаление требует ввести ник и удаляет принадлежащие пользователю рабочие деревья и публикации; независимые копии других пользователей сохраняются. Управляющие действия записываются в `admin_events` без паролей и почтовых токенов.

В Icon library: загрузка PNG/JPEG/WebP до 1 МБ и 1024×1024, название и категория. Только администратор может загружать изображения. Сервер декодирует файл через Pillow, отвергает SVG/анимацию и сохраняет очищенную PNG-иконку 128×128 в SQLite. Они появляются в общем выборе талантов, способностей, эмблем и аватаров. Удаление скрывает иконку из каталога, а сам файл сохраняется для уже созданных деревьев. Есть восстановление. Обычная загрузка собственных изображений пользователями по-прежнему запрещена.

### Письма подтверждения и восстановления

Настройки перечислены в [.env.example](.env.example). Их нужно передать **в окружение процесса**, например через systemd `EnvironmentFile`; сервер не загружает `.env` автоматически. Реальные SMTP-пароли не должны попадать в Git. Для публичного сайта нужны HTTPS и `COOKIE_SECURE=1`.

| Переменная | Назначение |
|---|---|
| `APP_URL` | Внешний HTTPS-адрес сайта без пути, например `https://talentforge.example` |
| `SMTP_HOST`, `SMTP_PORT` | SMTP-сервер и порт; по умолчанию 587 с STARTTLS |
| `SMTP_SSL` | `1` для SMTPS, обычно порт 465; иначе STARTTLS |
| `SMTP_USER`, `SMTP_PASSWORD` | Учётные данные почтового сервиса |
| `SMTP_FROM` | Подтверждённый у провайдера адрес отправителя |
| `REQUIRE_EMAIL_VERIFICATION` | `1` — вход новых почтовых аккаунтов только после подтверждения; `0` — можно войти сразу |

По умолчанию требование подтверждения выключено, чтобы локальная регистрация работала без почтового провайдера; интерфейс честно показывает неподтверждённую почту. После настройки SMTP проверить доставку и включить `REQUIRE_EMAIL_VERIFICATION=1`. Старые аккаунты без почты сохраняют вход по логину и могут добавить адрес в профиле. Если SMTP не настроен, восстановление/повторная отправка показывают сообщение о необходимости настройки, а не притворяются отправкой письма.

Подтверждение действует 24 часа, сброс пароля — 30 минут. В базе хранятся только хеши одноразовых токенов. Ссылки открываются на `/account.html`, подтверждение выполняется нажатием кнопки; ссылка сброса открывает форму нового пароля. После сброса завершаются обычные и административные сессии. Почтовые токены передаются во фрагменте URL, очищаются из адресной строки и не попадают в HTTP-журнал. В форме входа есть «Забыли пароль?» и повторная отправка подтверждения.

Проверки: `python3 -m unittest discover -s tests -p 'test_*.py'`; браузерный сценарий `python3 tests/browser_accounts_admin.py` проверяет регистрацию по почте, отдельную админ-сессию, блокировку, загрузку и удаление иконки, её появление в обычном редакторе и подтверждение/сброс через тестовый почтовый ящик. Тесты не отправляют настоящих писем и используют временные базы.


### Категории иконок, черновики и архив деревьев

В `/admin` → **Icon library** администратор создаёт категории, переименовывает их и выбирает тип: общий, оружие или доспехи. Кнопка **Edit** у загруженной иконки меняет её категорию и теги. Пользовательские категории появляются в общем выборе иконок; тип также определяет попадание в фильтры оружия и доспехов. Для удаления категории сначала перенесите её иконки, включая скрытые, в другую категорию. Стандартные категории удалить нельзя.

В **Моих деревьях** карточка открывается целиком, в том числе клавишами Enter/Space. Непубликованные сохранения помечены как **Черновик**. Рядом с поиском находится **Архив**, внутри него — **Вернуться в активные**. У каждой удалённой записи виден оставшийся срок до окончательного удаления, с обновлением раз в минуту, и кнопка восстановления.

Удаление рабочего дерева отправляет его и активные публикации в архив, закрывая их ссылки и убирая их из рейтинга. Восстановление дерева возвращает эти публикации с прежними ссылками и статистикой; версии, отправленные в архив отдельно, остаются там. Отдельную публикацию можно удалить кнопкой **Удалить** в «Моих публикациях». Обе операции предваряются окном с предупреждением о 30 днях хранения. Через 30 суток удаление окончательное; чужие независимые копии сохраняются. Миграция базы выполняется автоматически при запуске сервера.

В чужом опубликованном дереве вместо «Редактор» показано **Скопировать себе**. Кнопка сохраняет независимую копию в черновики текущего пользователя и открывает редактор. Для гостя сначала открывается вход, затем копирование продолжается. Оригинал автора не меняется, распределённые очки остаются только в браузере.

Проверки: `python3 tests/browser_tree_archive_copy.py` и `python3 tests/browser_accounts_admin.py` (Playwright + Chromium, временные базы).


### Массовая загрузка иконок

В `/admin` → **Icon library** можно выбрать до 100 файлов одновременно. У каждого показаны миниатюра, имя файла, редактируемое название, категория и результат проверки. Название предлагается из имени файла; общая категория применяется к ещё не загруженным допустимым файлам, отдельную категорию можно изменить в строке. Файл можно убрать из списка до отправки.

Проверка сравнивает пиксели обработанных иконок 128×128, поэтому переименование и изменение метаданных PNG не обходят запрет дублей. Учитываются активные и скрытые загруженные иконки в базе, а также повторы в текущем выборе. Для скрытой иконки предлагается восстановление через каталог. Перед записью сервер повторяет проверку в транзакции, защищая от одновременной загрузки одного изображения. Файлы отправляются отдельно: лимит API остаётся прежним, а ошибка одного файла не отменяет остальные. Неудавшуюся загрузку можно повторить из списка.

Форматы и ограничения иконок прежние: статические PNG/JPEG/WebP, до 1 МБ и 16–1024 пикселей по каждой стороне. Старые загруженные иконки автоматически индексируются при запуске; существующие ссылки и изображения сохраняются.

### «О проекте» и способы помощи

В верхнем меню появился общедоступный раздел **О проекте** (**About** в английском интерфейсе), также доступный по `/#about`. В `/admin` → **Project settings** редактируются описание и список способов помощи. Есть поля English/Русский; при отсутствии перевода используется заполненный вариант другого языка. Это ручные тексты администратора, автоматического перевода нет.

Каждая карточка помощи содержит название, текст с переносами, необязательную ссылку с подписью, изображение и отдельную ссылку по нажатию на изображение. Изображение можно указать внешним HTTP(S)-адресом или загрузить PNG/JPEG/WebP до 1 МБ и 2048×2048. Загруженная картинка очищается от метаданных и сохраняется в PNG, пропорции сохраняются, большая сторона ограничивается 1600 пикселями. Карточки можно добавлять, удалять и менять местами; доступны предварительный просмотр и сохранение всего раздела. Если другой администратор уже изменил настройки, устаревшая версия не перезапишет их.

Первоначальное описание объясняет возможности TalentForge; начальные способы помощи — рассказать о проекте, сообщить об ошибке и помочь в разработке. Собственные платёжные ссылки, баннеры и другие способы поддержки администратор добавляет сам.

Проверка: `python3 tests/browser_bulk_about.py` (Playwright + Chromium, временная база). Дополнительных зависимостей, кроме уже используемой Pillow, не требуется; миграции базы выполняются при запуске сервера.


### Масштаб иконок в рамке

Загруженные иконки автоматически заполняют рамку: маленькие увеличиваются, большие уменьшаются с сохранением пропорций и обрезкой по квадрату. При отображении отбрасываются прозрачные внешние поля и однотонные почти чёрные внешние поля; цветные рамки сохраняются. Подгонка работает для уже загруженных иконок, списка файлов перед загрузкой и общего выбора иконок. Исходные изображения, идентификаторы и проверка дублей в базе не изменяются.

Проверка: `python3 tests/browser_icon_fit.py` (Chromium/Playwright, временная база).


### Теги и поиск иконок

У загруженных иконок есть отдельное поле **Tags**: например, `лёд, ice, frost, маг`. При массовой загрузке **Tags for selected files** задаёт общие теги для ещё не загруженных допустимых файлов; в строке каждой иконки их можно отредактировать отдельно. Для уже загруженных иконок откройте **Edit** в каталоге администратора. Пустое поле удаляет теги; редактирование скрытой иконки не возвращает её в общий каталог.

Поиск в админке и во всех общих окнах выбора иконок учитывает название, внутреннее имя и теги. Регистр и различие «е/ё» не влияют на поиск; несколько введённых слов должны найтись в этих полях, даже если находятся в разных тегах. Теги отделяются запятыми (также принимаются `;` и переносы строк); повторы удаляются. Допускается до 30 тегов, до 50 символов каждый и до 1000 символов всего. Русские и английские синонимы вводятся вручную.

Миграция добавляет поле в существующую базу автоматически: прежние иконки получают пустые теги. Изображения и идентификаторы сохраняются.


### Иконки в дереве и редакторе таланта

Одинаковая подгонка рисунка применяется в ячейках дерева, редакторе таланта и его предпросмотре, калькуляторе и эмблемах. Поддерживаются загруженные и встроенные изображения; для внешних картинок используется отдельное чтение с CORS, при недоступности которого исходная картинка остаётся видимой. Рисунок заполняет внутреннюю область рамки независимо от его исходного размера.

Поиск по тегам в редакторе не зависит от успешной загрузки стандартных JSON-каталогов: пользовательские иконки и теги подгружаются отдельно. Допускаются запросы с `#`, например `#лед #маг`. Поиск находится в верхнем поле «Название или теги»; поле «Прямое имя WoW-иконки» задаёт точное системное имя.
