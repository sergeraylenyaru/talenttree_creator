# Редактор способностей и продолжение тренировки

Основной редактор (`editAbility`) общий для дерева, связанного таланта, библиотеки,
дубликата, импорта способности и контекстного меню панели. Основные поля и резюме
видны сразу; коэффициенты, правила обновления аур, условия изучения, оформление,
проки и прочие настройки остаются в существующих дополнительных разделах.
Проки по-прежнему редактируются существующим конструктором правил персонажа.
Ресурсы и единицы берутся из текущего класса. Невалидные комбинации отклоняют
существующие валидаторы; скрытие поля не стирает его значение.

## Как продолжить бой

- «Вернуться к дереву» и Escape без активного каста сохраняют сцену и runtime на паузе.
  Escape во время каста сохраняет прежнее поведение: прерывает каст.
- Повторное открытие того же класса продолжает эту сессию. Сцена, mixers, камера,
  выбранный манекен, раскладка и панели остаются теми же объектами.
- Время в дереве, меню и редакторе исключается из часов боя. Пауза останавливает
  движение, физику, анимации, автоатаку, снаряды, ауры, регенерацию и RNG.
- Меню и редактор используют вложенные удержания паузы: передача из меню редактору
  не запускает бой между окнами. Последнее закрытие восстанавливает исходную паузу.
- ПКМ по авторской способности открывает единственный пункт «Редактировать».
  Сохраняется исходный ID экземпляра текущего класса. Отмена не сохраняет черновик.
  Пустые слоты не открывают меню; для базовой автоатаки показывается объяснение
  о настройке в экипировке. Режим калькулятора, чужие и избранные деревья не дают
  права редактирования через тренировку.

## Правила применения изменений

| Состояние | После сохранения способности |
| --- | --- |
| Уже начатый каст/канал | Доделывается прежняя скомпилированная запись: эффекты, стоимость, время, доставка и настройки канала. Удаление записи не отменяет начатое действие. |
| Выпущенный снаряд | Сохраняет прежний профиль полёта, эффект и однократный callback попадания. Удаление источника не уничтожает снаряд. |
| Наложенная аура/DoT/HoT/щит | Сохраняет эффект, стаки, следующий тик, срок и остаток щита. Следующее применение использует новые настройки и обычные правила обновления аур. |
| Следующее применение | Получает актуальную запись с тем же ID. Заблокированная талантом или удалённая способность больше не применяется. |
| Прошлый журнал и аналитика | Не пересчитываются и не переименовываются задним числом. |
| Cooldown, заряды, swing, руны, DR, ICD проков | Сохраняются существующие очереди и часы. Новые параметры используются дальше; скорость swing/рун пересчитывается обычными правилами haste. |
| HP и ресурсы | Сохраняется абсолютное текущее значение с ограничением новым максимумом. Увеличение максимума не лечит и не заполняет ресурс. Смерть не воскрешает. |

Прежняя запись действия не означает фиксацию всех характеристик мира. Обычные
неснапшотные эффекты используют текущие характеристики/баффы при расчёте, а
процентная стоимость — актуальный максимум ресурса. Флаг snapshot у периодического
эффекта продолжает использовать существующее поведение движка. Расчёт урона,
лечения и оплата остаются в том же combat-runtime, отдельного движка нет.

При обычных изменениях статов, экипировки, уровня и талантов пересобираются только
будущие lookup-таблицы и производные максимумы. Для другого проекта/черновика,
смены базового класса/версии правил, seed, состава/единиц/типа ресурсов или сценария
входящего урона появляется явный выбор: продолжить прежний бой, начать новый либо
остаться в дереве. Прежняя сессия не уничтожается до выбора новой.

«Сбросить бой» остаётся отдельным действием. Выход из аккаунта освобождает сессию.
Закрытие/обновление страницы не сохраняет бой; сохранённый проект и параметры
способностей загружаются обычным способом. Отдельный 3D-предпросмотр по-прежнему
является отдельной сессией и требует явной замены сохранённой тренировки.
В редакторе поверх тренировки отдельный предпросмотр скрыт: сохранение возвращает
в тот же бой. Пользовательские базы и приватный репозиторий не изменяются.

## Проверки

```sh
npm test
python -m unittest discover -s tests
npm run build
python tests/browser_editor_fields.py
python tests/browser_ability_isolation.py /tmp/editor-isolation
python tests/browser_editor_session.py /tmp/editor-session
python tests/browser_spell_workshop.py /tmp/editor-workshop
```

Chromium-сценарий `browser_editor_session.py` использует **четыре настоящих GLB** из
игнорируемого `local-assets/wow` и WebGL2 (SwiftShader на облачном Linux). Он сравнивает
снимки runtime/камеры/положения/цели/панели/таймеров/RNG при трёх возвратах, проверяет
старый урон 100 и новый 500, каст, DoT, cooldown, снаряд, автоатаку, меню, отмену,
прежнюю паузу, удаление, горячую клавишу, таланты, максимумы, права, смену класса и
повторную загрузку сохранённого проекта. При паузе отсчёт фиксируется на обработке
нажатия, включая допустимый остаток времени после последнего отрисованного кадра.

`browser_editor_fields.py` проверяет сохранение скрытых настроек и контекстные поля
через реальный UI, **без 3D и без модельных утверждений**. `session-continuity.test.js`
проверяет движок на синтетических документах и delivery-функциях. Это отдельные
регрессии, не подмена испытаний настоящих моделей. Все браузерные тесты используют
временные SQLite, исходная пользовательская БД не служит тестовой базой.
Windows 11 и аппаратные GPU этим облачным прогоном не проверяются.
