# Изоляция экземпляров способностей

Базовая версия — Task 15.1, коммит b37d56037e7d268d7a4edfde2050da4f65f466f7.

Библиотечная запись служит источником для копии. Перетаскивание на дерево, выбор через диалог узла и дублирование создают новый UUID и глубокую копию настроек. Поле templateSource сохраняет ID и название источника для справки. Боевой движок исполняет настройки экземпляра.

Сохранённый личный шаблон содержит снимок настроек и связанных боевых правил. При переносе в другой документ правила получают новые ID и привязываются к доступности нового экземпляра. Это устраняет зависимость от ID таланта исходного дерева. Таланты и предметы, которые усиливают способность в текущем документе, сохраняют свои условия при дублировании внутри документа.

Существующие документы загружаются с прежними ID, привязками и сохранёнными билдами. Перемещение узла вызывает прежний moveTalent и сохраняет экземпляр. Автоматическая замена старых ID не выполняется.

Личные шаблоны Workshop хранятся в браузере отдельно для каждого логина. Старый общий список остаётся в хранилище. При первом обращении зарегистрированного пользователя к старому списку этот логин получает его копию. Это правило миграции требуется, поскольку предыдущий формат не содержал владельца. Синхронизация этих шаблонов между браузерами использует существующий экспорт и избранное.

Базовый урон нового стандартного Огненного шара задан равным 150 по сценарию пользователя. Это предварительное значение Talent Forge. Сохранённые пользовательские экземпляры сохраняют свой урон.

Проверка browser_ability_isolation.py создаёт два дерева мага через интерфейс и копирует библиотечную способность в узлы событиями drag/drop. Первый экземпляр получает 500 урона, второй сохраняет 150, стандартный шаблон сохраняет 150. Дубликат получает 700. Личный шаблон сохраняет снимок 500. После перезапуска Chromium и HTTP-сервера все значения проверяются повторно, включая два сохранённых билда и ID перемещённого узла.

Task 17 расширяет копирование транзитивными proc payloads и cooldown-ссылками. Зависимые способности получают собственные ID и instanceOwnerId, включаются вместе с владельцем и удаляются вместе с ним. Workshop, избранное и сохранённые билды содержат независимые снимки. Ресурсные ссылки переназначаются согласованно при импорте в другой класс. Отдельный browser_template_dependencies.py проверяет изменения 700/25, расчёт 850 урона с остатком 88 ресурса и сохранность после перезапуска.
