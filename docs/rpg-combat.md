# Character Lab and combat analysis

Open **Character Lab** from a class in edit mode. Configure attributes and scaling in **Statistics**, create and equip items in **Equipment**, and attach bonuses or triggers to existing talents, passive abilities, or items. Define combat effects in the **Spell Workshop**. The lab saves to the class draft. Use the class **Save** action to store that draft in your account.

Enter **Training Grounds** and control the hero with the existing action bar and movement controls. The dummy is the only hostile target. To test defenses, configure **Enable controlled incoming damage** in the Character tab, then use **Test dummy strike** in the arena. Its configured raw damage and school pass through the standard damage calculation. This action also lets you test player health thresholds, regeneration, and overhealing.

## Class data

The optional `rpg.version: 1` profile adds base attributes, scaling coefficients, an equipment library, active slot assignments, class and level restrictions, Haste scope, resource rules, talent/passive/item bonuses, proc rules, named talent and equipment snapshots, and measurement settings. Existing classes work with their prior defaults. Workshop effects retain their existing IDs and can also declare shields, resource drains, stat snapshots, weapon scaling, school-specific damage bonuses, and effects consumed on a direct hit. Item quality is descriptive. Weapon range of damage and swing interval come from the equipped item. Off-hand weapons swing independently at half damage when dual wield is enabled. A shield can occupy the off hand without contributing a swing.

Primary attributes support configurable additive scaling into secondary attributes and resource maxima. Each formula adds the selected primary value multiplied by its coefficient. Base stats, eligible passive and talent bonuses, and gear contribute before formulas. Timed stat changes are evaluated when an effect resolves. For example, assign a Strength to Attack Power coefficient of 2 or a Stamina to maximum health coefficient of 10. Haste accelerates only the selected systems. Cooldown recovery is a separate cooldown modifier. The character editor and live arena panel use the same derived stat calculation.

## Resolution order

1. Validate the action, spatial target, costs, and timing. A paid projectile must contact the dummy to apply its hostile payload.
2. Build the source sheet using class values, gear, learned talents and passives, scaling formulas, and active effects. A periodic snapshot freezes the attacker sheet at application. Target mitigation and vulnerability are read at each tick.
3. Roll base weapon or ability damage where a range is configured. Add the declared scaling and flat bonuses. A physical ability can use a coefficient of the relevant equipped weapon's average damage.
4. Apply the source, ability, school and target multipliers, then roll critical contribution when eligible. Physical damage uses armor. Magic uses the matching school resistance.
5. Round the mitigated amount. Incoming damage consumes shields in priority order, with older shields breaking ties. Each shield takes its fraction of the remaining packet, up to its remaining capacity.
6. Apply health changes. Healing records its raw, modified, effective, and overhealing values. Damage reports the original, bonus, critical, mitigated, absorbed, and final values, with overkill separated.
7. Record structured events, update analytics, and evaluate eligible triggers. Trigger effects reuse existing ability effect definitions. Events generated by a proc cannot trigger another generation.

Periodic ticks and effect expiration use the combat clock. A tick scheduled exactly at expiration runs first. Refresh, refresh without stacking, preserve remaining duration, replace, extend, and bounded independent stacks are available. Resetting combat clears active effects, pending impacts, cooldowns, proc state and session metrics. **Reset dummy** instead restores its health and clears hostile effects while preserving the accumulated measurement.

## Comparing runs

Open **Combat analysis** while in the arena. Review cumulative metrics, ability and school contributions, status and proc statistics, a timeline, and the runtime character sheet. Use **Stop session**, **Resume session**, or **New session** to control the measurement. Export JSON or CSV with the build, conditions, seed, and captured events. Saved measurements stay in the current browser. A named build in Character Lab stores its selected specialization, talent allocation, and equipment slots in the class document.

For reproducible comparisons, use the same seed, duration and dummy settings, then repeat the same actions. The comparison marks different durations, seeds, or arena settings. The timeline retains the last 5,000 events and the totals cover the full session. The portrait and weapon visual come from the existing local models. The current asset set provides one sword visual, so other weapon types use authored combat values with the arena's current art.
