# Wowhead 19019: служебные поля и регрессия

База исправления: `004377d6d236325f41c845b24b89664279ff31f2` (ветка редактора,
содержащая импорт Wowhead). Рабочая ветка: `codex/wowhead-cata-service-fields`.
Исходные опубликованные ветки, пользовательские БД и приватные ассеты не меняются.

## Причина и назначение полей

На фактическом XML, присланном пользователем из Windows, прежний парсер возвращал:
`unsupported_stats: displayid, dmgrange, dura, maxcount, sheathtype, slotbak`.
JSON-фрагмент `jsonEquip` содержит не только боевые характеристики.

| Поле | Назначение и обработка |
| --- | --- |
| `displayid` | Идентификатор внешнего вида/модели. Не stat; не заменяет XML icon. |
| `dmgrange` | Служебный параметр разброса исходного урона. Не отдельная характеристика героя. Не используется для повторного вычисления уже переданных `dmgmin1/dmgmax1`. |
| `dura` | Максимальная прочность, 130 в этом ответе. Износ не моделируется. |
| `sheathtype` | Тип положения оружия в убранном состоянии. Не меняет руки/доступность экипировки и не калибрует GLB. |
| `slotbak` | Внутреннее резервное представление слота Wowhead. Авторитетным остаётся существующий XML `inventorySlot` с проверкой согласованности основного JSON `slot`. |
| `maxcount` | Ограничение количества экземпляров, не stat. Значение 1 переводится в существующий `uniqueGroup`: нельзя надеть две копии. Библиотека хранит независимые шаблоны, не является инвентарём сумок. Лимит владения в сумках не симулируется. Противоречивые значения между JSON-фрагментами отклоняются. |

Пять служебных полей перечислены **по точным именам**, с проверкой числового
формата, границ и целочисленности там, где она нужна. Их пояснения сохраняются в
существующих `source.unmodeled` и показываются в предпросмотре/источнике предмета
по-русски и по-английски. `maxcount` обрабатывается отдельно как ограничение.
Неизвестные числовые поля `jsonEquip`, включая похожие имена `displayid_bonus`,
по-прежнему дают `unsupported_stats`; неизвестные/неподдерживаемые требования
продолжают отклоняться. Общих разрешений по префиксу и отключения валидаторов нет.

Контекст назначения обычных полей предмета проверен по Cata-структурам
[ItemSparseEntry](https://github.com/TrinityCore/TrinityCore/blob/cata_classic/src/server/game/DataStores/DB2Structure.h)
(`DmgVariance`, `MaxCount`, `SheatheType`) и
[ItemTemplate](https://github.com/TrinityCore/TrinityCore/blob/cata_classic/src/server/game/Entities/Item/ItemTemplate.h)
(`GetMaxCount`, `MaxDurability`, `GetInventoryType`). Это справка о семантике полей,
не гарантия официального контракта Wowhead и не источник чисел импортируемого предмета.
Все числа регрессии взяты только из присланного `/cata` XML.

## Что именно импортируется из этого XML

Thunderfury, Legendary, ilvl 80, уровень героя 60, меч для правой или левой руки,
ловкость 5, выносливость 8, скорость 1.90. Сохраняются переданные точные числа
`43.999998855590825` и `115.00000343322755` (tooltip округляет их до 44–115).
Значение DPS 53.95 не подменяет физический диапазон: оно включает дополнительный
урон природы из описания. Физический DPS данных границ — около 41.84.

`jsonUse.natres=-25` — часть эффекта предмета, **не постоянное сопротивление героя**.
В предпросмотре явно указана необходимость ручной настройки jsonUse. Прок 300
Nature damage, его переходы на другие цели, дополнительный Nature damage 16–30 и
сопротивления +8 Fire/+9 Nature встречаются только в tooltip этого ответа и не
создаются автоматически как механики/статы. Они сохраняются описанием; коэффициенты
и вероятность прока не угадываются. Другие цели не добавляются.

## Фактически выполненные проверки

- Присланный XML неизменён в `tests/fixtures/wowhead-cata/19019.xml`; происхождение
  и SHA256 сохранённой копии указаны в README рядом. Старая версия воспроизвела
  ровно шесть полей ошибки; новая принимает этот же документ.
- 6 новых Python-регрессий: реальные поля и числа, отсутствие подмены уроном DPS,
  служебные поля не влияют на статы/слот, неизвестные статы/требования отклоняются,
  некорректная metadata/конфликт maxcount отклоняется, maxcount=1 работает независимо
  от слова Unique в tooltip на клиенте и сервере, preview не сохраняет предмет сам.
- Полный Python: **110/110**. Node.js: **332/332**. `npm run build`: успешно.
- Chromium: ID и XML-ссылка → предпросмотр → подтверждение двух независимых копий →
  изменение одной → проверка уникальности → экипировка существующим способом →
  сохранение → перезапуск браузера/тестового сервера → повторное открытие без источника.
  Получены и просмотрены скриншоты. Использовался реальный XML пользователя с
  подменой только загрузчика `fetch_xml`; это не успешный live HTTP и не GLB-тест.
- Живой `preview('19019')` проверен отдельно и вернул `source_unavailable` за ~0.015 с.
  Прямой curl подтверждает **HTTPS CONNECT 403** облачного proxy. Домена
  `www.wowhead.com` нет в применённом списке доступа этой среды. Успешный live-import
  в облаке **не подтверждён**; это не опровергает рабочий запрос на Windows пользователя.

Автоматические регрессии не зависят от доступности Wowhead:

```sh
python -m unittest discover -s tests -p 'test_wowhead_19019.py'
python tests/browser_wowhead_19019.py /tmp/wowhead-19019
```

Для живой проверки отдельно (при доступном источнике):

```python
import wowhead_items
item = wowhead_items.preview('19019')
print(item['name'], item['stats'], item['minDamage'], item['maxDamage'], item['speed'])
```

## Windows: применение патча без сброса проекта

Сначала остановить сервер. Команды выполняются в своей тестовой копии проекта,
куда скачан `wowhead-19019-service-fields.patch`. Применение не трогает БД/модели.

```powershell
git status --short
git apply --check .\wowhead-19019-service-fields.patch
git apply .\wowhead-19019-service-fields.patch
& .\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_wowhead_19019.py'
# Запустить сервер прежним способом и обновить страницу Ctrl+F5.
```

Затем «Персонаж и экипировка → Экипировка → Импорт из Wowhead», ID `19019`,
Cataclysm, загрузка, сверка данных, подтверждение, сохранение персонажа и проекта.
Предмет не надевается автоматически. Проверить повторное открытие после перезапуска.
Перед откатом остановить сервер; `git apply -R --check` и `git apply -R` с тем же
патчем удаляют только это исправление, если контекст не менялся. `reset` не нужен.
