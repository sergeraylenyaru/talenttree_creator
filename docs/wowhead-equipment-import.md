# Импорт экипировки Wowhead Cataclysm

База: `7dcd4f3ddb1dd3ad684f5614e6a9c6c5dddda5b0`. Отдельная ветка `codex/wowhead-cata-equipment-import`, рабочая копия `/workspace/talentforge-wowhead`. Прежняя опубликованная ветка и приватный репозиторий ассетов не изменяются. Публикации этой доработки нет.

## Изученная система и решение

| Система | Исходное состояние | Изменение |
|---|---|---|
| `AGENTS.md` | Один герой, один манекен, прежняя арена | Граница сохранена; импортирует только данные предмета |
| `static/character-lab.js` | Библиотека предметов, JSON import/export, equip, duplicate, builds | Добавлен Wowhead preview/confirm, сохранён прежний способ надевания |
| `static/combat/rpg-profile.js`, `rpg_profile.py` | Жёсткий один slot, один requiredClass, ограниченный набор типов | Optional allowedSlots/requiredClasses/uniqueGroup/source; одинаковые проверки клиента и сервера |
| `character-stats.js`, `combat-runtime.js` | Суммирование статов экипировки и weapon/AP damage | Используются без второго движка; новые виды оружия подключены к прежним таймерам и нормализации |
| `server.py` | Авторизованные JSON API и сохранение документа | POST `/api/items/wowhead/preview`, без создания проекта/предмета в БД до обычного сохранения пользователем |
| Сохранённые builds | Независимые полные snapshots | Импортированные предметы и provenance входят в прежний snapshot, не зависят от сети |

## Сценарий

**Персонаж и экипировка → Экипировка → Импорт из Wowhead.**

1. Выберите единственную поддерживаемую версию **Wowhead Cataclysm (/cata)**; она явно видна и для числового ID.
2. Введите `19019` либо `https://www.wowhead.com/cata/item=19019`. Допускается предоставленная пользователем XML-ссылка с `&xml`, slug и известный языковой сегмент; сервер всё равно формирует собственный канонический английский `/cata/item=ID&xml`.
3. Нажмите **Загрузить предпросмотр**. До подтверждения библиотека и экипировка не меняются.
4. Проверьте имя, icon ID, качество, item level, required level/classes, тип, допустимые слоты, броню, статы и диапазон/скорость оружия. Раскройте источник и текст tooltip; там же показаны перенесённые поля и неавтоматизированные эффекты.
5. Нажмите **Добавить независимую копию**. Создаётся новый UUID; повторный импорт не заменяет существующий предмет. Предмет автоматически не надевается.
6. Наденьте предмет прежней кнопкой **Equip selected item** или выпадающим списком нужного слота. Для Ring2/Trinket2 доступны соответствующие копии; одну физическую копию нельзя одновременно надеть в два слота.
7. Сохраните окно персонажа, затем проект в аккаунте. При необходимости сохраните build. Повторная загрузка использует сохранённые поля, не Wowhead.
8. **Настроить эффекты предмета** открывает существующий раздел баффов/дебаффов с модификаторами и триггерами; источником можно выбрать предмет. Прок, use, set или socket не создаётся из текста автоматически.

Классовые ограничения проверяются по `rpg.combatRules.classId`. Без выбранного базового combat class ограниченный предмет не надевается. Старые предметы с одним `slot` и `requiredClass` сохраняют прежнюю семантику. Новые поля необязательные; версия документа не меняется.

## Поддержанные данные

- Источник/версия/числовой ID, каноническая ссылка, UTC-время загрузки, SHA256 исходного XML, исходный inventorySlot/subclass, список перенесённых полей и plain-text tooltip сохраняются в `item.source`.
- Имя из XML, валидированное имя иконки, quality 0–5, item level, required level, XML/JSON class restrictions (включая bitmask) переносятся без определения класса по названию предмета.
- Strength/Agility/Stamina/Intellect/Spirit; AP/SP/healing power; hit/crit/haste/expertise/mastery/dodge/parry/block ratings; плоское HP, spell penetration и распознаваемые сопротивления. Ненулевые неизвестные числовые статы отклоняются, а не подменяются похожими.
- Единый Cata `hitrtng` записывается в обе существующие сырые шкалы `hitRating` и `spellHitRating`: расчёт каждой таблицы использует свою конверсию. Это не удвоение рейтинга внутри одной таблицы.
- Одноручные sword/axe/mace, dagger, fist; двуручные sword/axe/mace/staff/polearm; bow/crossbow/gun; cloth/leather/mail/plate, necklace/cloak/ring/trinket, shield и held-in-offhand.
- InventorySlot 13 разрешает main/off, 21 — только main, 22 — только off, 17 — только main с занятием обеих рук. Shield и holdable не требуют dual wield; оружие в offhand требует разрешения. Двуручное оружие блокирует любой offhand.
- Ring1/Ring2 и Trinket1/Trinket2 поддержаны через allowedSlots. Повторное надевание одного UUID блокируется. Распознанные простые Unique/Unique-Equipped ограничения образуют уникальную группу исходного ID; библиотечные копии остаются независимыми.

Дополнительные типы расширяют прежнюю модель предметов и её валидаторы, без переименования старых `axe`/`mace`. Их two-hand normalization и выбор ranged weapon используют существующий расчёт. Импорт не скачивает 3D-модели предметов; в сцене остаются прежние приватные модели героя, манекена, меча и окружения.

## Явные ограничения

Это наблюдаемый XML сайта, **не официальный гарантированный API**. Namespace `/cata` обозначает Wowhead Cataclysm; соответствие оригинальным DBC build15595 не доказано. Retail, Classic Era, WotLK и другие URL отклоняются. Параметры bonus/уровня/суффикса/варианта не игнорируются молча — запрос отклоняется.

Проки, use-эффекты, set bonuses, sockets, enchants и random properties не превращаются в правила боя. Часть распознаётся как отдельные предупреждения, полный tooltip доступен обычным текстом. Никакие coefficients, chance или ICD из текста не придумываются. `setId` автоматически не устанавливается.

Дополнительная составляющая урона второй школы отмечается как неперенесённая; основной физический диапазон переносится отдельно. Оружие с магической основной составляющей отклоняется. Wand может быть представлен существующей моделью, но типичная магическая wand не импортируется с фиктивным физическим уроном.

Не поддержаны реликвии, thrown/fishing и другие отсутствующие типы, heirloom/scaling items, сложные групповые unique limits, невыразимые skill/race/reputation/faction requirements. Mana/5, ranged-only AP, resilience, armor-penetration rating и старый shield block value нельзя подменить общими ресурсами/AP/процентами; такие ненулевые поля отклоняются с объяснением. Поддержка конкретного предмета зависит от его полей.

Icon ID хранится в документе. Изображение использует существующий необязательный CDN иконок; недоступность картинки не препятствует открытию/надеванию предмета. Для сохранённых предметов не вызывается API импорта и не требуется XML Wowhead. Предыдущие приближения combat profile не объявляются точными от одного только импорта item stats.

## Сеть и безопасное отображение

- Только авторизованный `POST` с `reference` и `version`; схема ссылки проверяется **до** сетевого запроса. Числовые ID 1…2147483647, только `https://wowhead.com` / `https://www.wowhead.com`, без userinfo/порта/произвольных query. URL создаётся сервером.
- Redirect запрещён, включая переход на другой хост; user-agent явно обозначает импортёр. Запрашивается несжатый XML. Никакие иконки, href или другие ссылки из ответа сервером не загружаются.
- Socket timeout 8 s, общий предел ожидания 12 s, максимум 2 000 000 bytes. Bounded daemon workers ограничивают даже зависший OS DNS: не более четырёх загрузок, permit удерживается до окончания IO. Лимит 60 попыток пользователя за 15 минут. SQLite write lock отпускается до загрузки.
- DTD/entity/неподдерживаемые кодировки отклоняются. JSON-фрагменты оборачиваются в `{…}` и разбираются строго; duplicate keys, NaN/Infinity и повреждённые структуры отклоняются. `eval` не используется.
- HTML tooltip превращается в текст, script/style/iframe/object/svg и HTML-атрибуты не выполняются. В DOM используются textContent и проверенная каноническая ссылка, исходный HTML в innerHTML не попадает.
- UI показывает loading/cancel, invalid reference, wrong version, not found, unsupported type/stats/requirements, timeout, blocked и unavailable. Изменение ввода/отмена инвалидирует устаревший ответ.

## Выполненные проверки

- Python: фиксированные синтетические XML для weapon/armor/ring/trinket; точные поля, ограничения типов/рук/классов, вторичная школа, отказ неизвестных статов, сопоставление JS/Python validators, HTTP authentication/no-network-on-invalid-input, независимые preview UUID, отсутствие записи в projects, size/deadline/redirect/error handling.
- Node: независимые deep copies; paired slots; unique/same-instance/dual-wield/two-hand/class/level gates; сохранение предмета; существующий sheet и combat runtime. Контроль: AP40 и HP+160 от weapon fixture, урон `120 + 40/14×2 → 126`.
- Chromium: интерфейс от загрузки XML **через серверный парсер** до подтверждения, повторного импорта, изменения первой копии 500–700 без изменения второй 100–140, надевания брони, двух колец и trinket во второй слот. Редактор эффектов открывается существующим путём.
- Chromium + browser/server restart: шесть копий и сохранённый build повторно открываются без preview API или fetch Wowhead. Внешние запросы браузера заблокированы тестом; optional icon errors не мешают.
- Реальная арена/WebGL2: четыре настоящих локальных GLB, imported fixture weapon в существующей формуле, AP120 после weapon+armor, ручной удар на **135**, export Combat report содержит происхождение предмета.
- Браузерные снимки предпросмотра и отчёта наблюдены. Это Linux Chromium/SwiftShader; нативная Windows 11 здесь не запускалась.

**Фикстуры вручную составлены под наблюдаемый формат. Их ID 900001–900004 и значения не являются живыми данными Wowhead.** README лежит рядом с XML. Браузер подменяет только сетевой транспорт; XML-парсер, серверная валидация, библиотека, сохранение, builds и combat engine — настоящие.

### Отдельная живая проверка

Выполнены прямой запрос указанного пользователем `https://www.wowhead.com/cata/item=19019&xml` и запрос через сам импортёр. Облачный proxy отверг HTTPS CONNECT с **403**, до получения ответа origin. Импортёр вернул `source_unavailable` за ~0.02 s. **Актуальный XML Wowhead и успешный импорт реального 19019 в этой среде не подтверждены.** Это не доказательство недоступности Wowhead на Windows пользователя и не тест успешной загрузки из сайта.

Детали и снимки: `/workspace/shared/wowhead-import/`. Пользовательские БД не использовались: HTTP/browser тесты имеют собственные временные SQLite. Приватный репозиторий и исходная опубликованная ветка сохраняются. Новых зависимостей Python или npm нет.

## Ручная проверка на Windows

1. В отдельной тестовой копии установите прежние зависимости, запустите сервер и войдите в аккаунт. Откройте Character Lab → Equipment → Import from Wowhead.
2. Введите `19019`, проверьте видимую версию Cataclysm и загрузите preview. Сверьте числа с XML на вашем ПК; не подтверждайте несовпадения. Для неподдержанного поля импорт даст объяснение.
3. Подтвердите, сохраните окно персонажа и проект; наденьте предмет прежней кнопкой. Повторите импорт, измените только одну копию и убедитесь, что другая не изменилась.
4. Импортируйте броню, кольцо и trinket; проверьте второй парный слот, уровень/класс и запрет offhand с two-hander. Посмотрите Derived statistics и ручной удар по единственному манекену.
5. Перезапустите сервер/браузер, при необходимости отключите сеть: сохранённые item data доступны. Проверьте Source/description и отсутствие автоматических проков/use/set/socket effects.

```powershell
# Запускается из рабочей копии с установленными прежними зависимостями:
$env:TALENT_LOCAL_WOW_ASSETS = '1'
$env:HOST = '127.0.0.1'
$env:PORT = '8000'
& .\.venv\Scripts\python.exe server.py
```

Повторные регрессии: `npm test`, `python -m unittest discover -s tests`, `npm run build`, `python tests/browser_wowhead_import.py <папка-снимков>`. Последний browser script в облаке использует установленный Chromium по Linux-пути; это не PowerShell-команда запуска Windows-браузера.

Итог регрессий этой ветки: **322 Node.js-теста и 104 Python-теста — PASS**, `npm run build` и `git diff --check` — PASS. Браузерный полный сценарий — PASS с фиксированным источником и настоящей 3D-ареной. Лог живого запроса хранится отдельно (`live-check.json`, `success: false`), не смешивается с этими результатами.
